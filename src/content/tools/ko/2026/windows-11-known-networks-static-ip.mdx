노트북 바탕화면에 `office.bat`, `home.bat` 두 개를 놓고 사는 사람이 아직도 많습니다. 사무실에 도착하면 `office.bat`을 관리자 권한으로 실행해서 고정 IP를 박고, 퇴근해서 집에 오면 `home.bat`으로 DHCP로 되돌리는 방식이죠.

```bat
:: office.bat — 15년째 대물림되는 그 파일
netsh interface ip set address name="이더넷" static 10.10.20.55 255.255.255.0 10.10.20.1
netsh interface ip set dns name="이더넷" static 10.10.10.10
```

이 방식은 Windows XP 시절에는 정답에 가까웠습니다. 하지만 지금은 **Windows 11이 네트워크(SSID)별로 IP 설정을 따로 기억해 줍니다.** 사무실 Wi-Fi에 붙으면 고정 IP, 집 공유기에 붙으면 DHCP — 손 대는 것 없이 자동으로 전환됩니다.

문제는 이 기능이 **기존에 어댑터에 직접 박아 놓은 수동 설정과 충돌**한다는 점입니다. 그래서 "설정했는데 안 되던데요?"라는 후기가 그렇게 많습니다. 이 글은 **초기화 → 설정 → 검증** 순서로, 실제로 동작하게 만드는 것까지 다룹니다.

## 30초 요약

| 상황 | 답 |
| :--- | :--- |
| 사무실·집 모두 **Wi-Fi**로 접속한다 | **알려진 네트워크 관리**에서 SSID별 IP 지정 → 완전 자동 |
| 사무실은 **유선 + DHCP 서버가 아예 없다** | TCP/IPv4 **대체 구성** 탭 → 자동 폴백 |
| 사무실은 **유선인데 DHCP도 돌아간다** | 대체 구성으로는 안 됨 → **DHCP 예약**이 정답 |
| 고정 IP가 필요한 이유가 "서버 접근 허용 목록" | 클라이언트가 아니라 **공유기·DHCP 서버에서 MAC 예약** |
| 예전 bat·수동 설정 흔적이 남아 있다 | 아래 **0단계 초기화**부터. 안 하면 십중팔구 안 됨 |

## 왜 bat 파일을 졸업해야 하나

netsh 스크립트가 나쁜 도구라서가 아닙니다. 운영 비용이 계속 나가기 때문입니다.

- **실행을 잊으면 그 순간 네트워크가 먹통.** 회의실 들어가서 화면 공유 안 되는 이유의 절반은 이것입니다.
- **매번 관리자 권한(UAC).** 잠금 해제하고, 예 누르고, 검은 창 뜨고.
- **인터페이스 이름 하드코딩.** `name="이더넷"`은 도킹 스테이션을 바꾸거나 USB 랜을 꽂는 순간 `이더넷 3`이 되어 조용히 실패합니다.
- **IPv6·DNS·프록시가 따로 논다.** 스크립트는 대개 IPv4만 건드리고, 나머지 잔재가 남아 이상한 증상을 만듭니다.
- **PC를 바꾸면 처음부터 다시.**

반면 프로필 방식은 **네트워크에 연결되는 순간 Windows가 알아서 적용**합니다. 사용자가 할 일이 없습니다.

## 0단계: 기존 수동 설정 초기화 (이 글의 핵심)

<Alert type="warning" title="이 단계를 건너뛰지 마세요">
어댑터 속성(TCP/IPv4)에 직접 넣은 고정 IP는 **어느 네트워크에 접속하든 무조건 적용되는 전역 설정**입니다. 이게 남아 있으면 SSID별 IP 설정이 무시되거나, 집에서도 사무실 IP가 그대로 유지돼 인터넷이 안 됩니다. 반드시 먼저 비워야 합니다.
</Alert>

### 1) 지금 상태 진단

명령 프롬프트나 PowerShell을 열고(관리자 권한 불필요):

```powershell
# 인터페이스 이름 확인 — 아래 명령들에 그대로 쓸 이름입니다
netsh interface show interface

# 어댑터별 IP 구성 한눈에 보기
netsh interface ip show config

# DHCP 사용 여부 확인
ipconfig /all
```

`ipconfig /all` 출력에서 **`DHCP 사용 . . . : 아니요`** 로 나오는 어댑터가 있다면, 그게 예전에 수동으로 박아 둔 설정입니다. `netsh interface ip show config` 출력의 `DHCP 사용: 아니요` / `정적으로 구성된 DNS 서버` 항목도 같이 확인하세요.

<Alert type="tip">
초기화하기 전에 **사무실 IP·서브넷·게이트웨이·DNS를 메모**해 두세요. 잠시 후 SSID별 설정에 그대로 입력해야 합니다. 지우고 나서 "그 IP가 뭐였더라" 하면 곤란해집니다.
</Alert>

### 2) 어댑터를 DHCP로 되돌리기

**GUI로:** 설정 → 네트워크 및 인터넷 → Wi-Fi(또는 이더넷) → **IP 할당** 옆 [편집] → **자동(DHCP)** → 저장. DNS 서버 할당도 마찬가지로 자동으로.

**명령으로(관리자 권한):**

```powershell
netsh interface ip set address name="Wi-Fi" source=dhcp
netsh interface ip set dns    name="Wi-Fi" source=dhcp

netsh interface ip set address name="이더넷" source=dhcp
netsh interface ip set dns    name="이더넷" source=dhcp

ipconfig /flushdns
```

가상 어댑터(VMware, Hyper-V, WSL, VPN)는 건드리지 마세요. 물리 Wi-Fi·이더넷만 대상입니다.

### 3) bat 파일이 남긴 잔재 청소

예전 스크립트는 IP만 바꾸지 않았습니다. 같이 확인할 것들:

```powershell
# 영구 정적 라우트 (route -p 로 추가된 것들)
route print
route delete 10.10.0.0            # 필요한 것만 골라서 삭제

# 시스템 프록시 (사내망 프록시를 스크립트로 넣어 뒀다면)
netsh winhttp show proxy
netsh winhttp reset proxy

# 잘못된 설정이 저장된 Wi-Fi 프로필 통째로 삭제 후 재접속
netsh wlan show profiles
netsh wlan delete profile name="OFFICE-WIFI"
```

`C:\Windows\System32\drivers\etc\hosts`에 사내 서버를 박아 둔 흔적도 이 김에 확인하면 좋습니다.

### 4) 그래도 이상하면 TCP/IP 스택 초기화

여기까지 해도 설정이 안 먹거나 재부팅하면 되돌아간다면:

```powershell
netsh winsock reset
netsh int ip reset
# 재부팅 필요
```

이 두 명령은 **저장된 Wi-Fi 비밀번호를 지우지 않습니다.** Winsock 카탈로그와 TCP/IP 레지스트리 키를 기본값으로 되돌릴 뿐이라, 비교적 안전한 선택지입니다.

### 5) 최후의 수단: 네트워크 초기화

설정 → 네트워크 및 인터넷 → **고급 네트워크 설정** → **네트워크 초기화** → 지금 다시 설정.

<Alert type="danger" title="네트워크 초기화의 대가">
모든 네트워크 어댑터를 제거 후 재설치합니다. **저장된 Wi-Fi 네트워크와 비밀번호, VPN 프로필, Hyper-V 가상 스위치, 모든 수동 IP 설정이 사라집니다.** 사내 VPN 클라이언트는 재설치가 필요할 수 있습니다. 4단계까지 시도한 뒤에도 해결되지 않을 때만 쓰세요. 약 5분 뒤 자동 재부팅됩니다.
</Alert>

## 1단계: Wi-Fi — 알려진 네트워크 관리에서 SSID별 IP 지정

여기가 본론입니다. Windows 11은 **저장된 Wi-Fi 프로필마다 IP 설정을 따로 보관**합니다.

1. **설정** → **네트워크 및 인터넷** → **Wi-Fi**
2. **알려진 네트워크 관리** 클릭
3. 고정 IP를 쓸 **사무실 SSID**를 선택
4. **IP 할당** 옆 **[편집]**
5. 드롭다운을 **자동(DHCP)** → **수동**으로 변경
6. **IPv4** 토글을 켜고 입력:
   - **IP 주소**: `10.10.20.55`
   - **서브넷 마스크**: `255.255.255.0` (빌드에 따라 "서브넷 접두사 길이"로 표시되면 `24` 입력)
   - **게이트웨이**: `10.10.20.1`
   - **기본 설정 DNS** / **보조 DNS**: 사내 DNS
7. **저장**

집·카페 SSID는 **아무것도 하지 않습니다.** 기본값인 자동(DHCP) 그대로 두면 됩니다.

이제 끝입니다. 사무실 Wi-Fi에 붙으면 고정 IP, 집에 오면 DHCP. bat 파일도, UAC 창도 없습니다.

<Alert type="info" title="주의: 프로필을 정확히 고르세요">
알려진 네트워크 목록에서 **엉뚱한 프로필을 수정하면 지금 쓰는 네트워크에는 아무 일도 일어나지 않습니다.** 현재 연결된 네트워크를 수정하면 저장 즉시 적용되고, 다른 프로필을 수정하면 다음에 그 네트워크에 접속할 때 적용됩니다.
</Alert>

### 같은 화면에서 함께 손보면 좋은 것들

프로필 상세 화면에는 IP 말고도 유용한 스위치가 있습니다.

| 항목 | 사무실 SSID | 집·카페 SSID |
| :--- | :--- | :--- |
| **자동으로 연결** | 켬 | 카페는 끄는 쪽을 권장 |
| **네트워크 프로필 유형** | 개인 (사내 공유·검색 필요 시) | 카페는 반드시 **공용** |
| **임의 하드웨어 주소** | **끔** | 켬 (프라이버시) |
| **종량제 연결** | 끔 | 테더링이면 켬 |
| **DNS over HTTPS** | 사내 DNS면 끔 | 켜면 DNS 도청 방지 |

<Alert type="warning" title="임의 하드웨어 주소(랜덤 MAC)가 진짜 범인일 때가 많습니다">
사내 네트워크가 MAC 주소 기반 DHCP 예약이나 NAC(접속 인증)를 쓴다면, 랜덤 MAC이 켜져 있는 순간 매번 다른 기기로 인식됩니다. "회사 와이파이만 자꾸 인증이 풀린다"의 단골 원인입니다. 사무실 SSID에서는 꺼두세요.
</Alert>

## 2단계: 유선(이더넷) — 대체 구성 탭

유선은 사정이 다릅니다. **이더넷의 IP 설정은 SSID 같은 식별자가 없어 어댑터 단위로만 저장**됩니다. 그래서 Wi-Fi처럼 깔끔하게 되지 않습니다.

대신 오래된, 그러나 여전히 유효한 기능이 있습니다. **대체 구성(Alternate Configuration)** 입니다.

### 설정 방법

1. **제어판** → 네트워크 및 공유 센터 → **어댑터 설정 변경**
   (또는 `Win + R` → `ncpa.cpl`)
2. 이더넷 어댑터 **우클릭 → 속성**
3. **인터넷 프로토콜 버전 4(TCP/IPv4)** 선택 → **속성**
4. 일반 탭이 **"자동으로 IP 주소 받기"** 상태인지 확인
   → 이때만 위쪽에 **[대체 구성]** 탭이 나타납니다
5. **대체 구성** 탭 → **사용자 구성** 선택 → 사무실 IP·서브넷·게이트웨이·DNS 입력 → 확인

### 동작 원리와 한계

DHCP 서버를 찾지 못하면(약 60초 타임아웃) Windows는 APIPA(`169.254.x.x`) 대신 **대체 구성에 적어둔 고정 IP를 적용**합니다. DHCP가 있는 집·카페에서는 평소대로 DHCP를 받고요.

<Alert type="danger" title="대체 구성이 통하지 않는 경우">
대체 구성은 **DHCP 서버가 응답하지 않을 때만** 발동하는 폴백입니다. 사무실에 DHCP 서버가 돌아가는데 "정책상 나는 고정 IP를 써야 한다"면 대체 구성은 영원히 발동하지 않습니다. 두 개의 IP를 동시에 쓰는 기능도 아닙니다. 또한 DHCP 타임아웃 때문에 **연결까지 최대 1분 정도 걸릴 수 있습니다.**
</Alert>

이 경우의 정답은 클라이언트가 아니라 서버 쪽에 있습니다. 아래 "진짜 해법"을 보세요.

## 3단계: 검증

설정만 하고 끝내면 안 됩니다. **네트워크를 실제로 바꿔가며** 확인하세요.

```powershell
# 현재 어댑터 구성 요약
Get-NetIPConfiguration -InterfaceAlias "Wi-Fi"

# DHCP 사용 여부만 콕 집어서
Get-NetIPInterface -InterfaceAlias "Wi-Fi" -AddressFamily IPv4 | Select-Object InterfaceAlias, Dhcp

# 게이트웨이까지 실제로 통하는지
Test-NetConnection 10.10.20.1
```

검증 시나리오는 이렇게:

1. 사무실 Wi-Fi 접속 → `ipconfig` 로 고정 IP 확인, `DHCP 사용: 아니요`
2. 집 Wi-Fi(또는 폰 핫스팟)로 전환 → `ipconfig` 로 DHCP IP 확인, `DHCP 사용: 예`
3. 다시 사무실 Wi-Fi → 고정 IP로 **자동 복귀**되는지 확인

3번까지 통과해야 진짜 끝난 겁니다. 2번에서 사무실 IP가 그대로 남아 있다면 **0단계 초기화가 덜 된 것**입니다. 어댑터 속성에 아직 수동 IP가 박혀 있는지 다시 확인하세요.

## 진짜 해법: DHCP 예약

한 걸음 물러서서 볼 필요가 있습니다. **왜 사무실에서 고정 IP가 필요한가요?**

대부분은 이런 이유입니다.

- 서버·DB 접근 허용 목록(방화벽 화이트리스트)에 내 IP가 등록돼 있어서
- 라이선스 서버가 IP로 기기를 식별해서
- 개발용 포트를 동료가 내 IP로 접속해야 해서

이 세 가지 모두 **DHCP 예약(DHCP Reservation)** 으로 해결됩니다. 공유기나 사내 DHCP 서버에서 **내 MAC 주소에 특정 IP를 고정 배정**하는 방식입니다.

| 구분 | 클라이언트 고정 IP | DHCP 예약 |
| :--- | :--- | :--- |
| 설정 위치 | PC마다 | 공유기·DHCP 서버 한 곳 |
| PC 설정 | 네트워크마다 다르게 | **어디서든 자동(DHCP) 그대로** |
| IP 충돌 위험 | 있음 (누가 이미 쓰는 IP를 박으면) | 없음 (서버가 관리) |
| PC 교체·재설치 | 다시 설정 | MAC만 등록하면 끝 |
| 유선·무선 구분 | 각각 설정 | 각각의 MAC 등록 |

<Alert type="success" title="이게 되는 환경이라면 1·2단계가 아예 필요 없습니다">
PC는 전 구간 DHCP로 두고, IP 고정은 서버가 책임집니다. 노트북 설정은 어디서든 손댈 것이 없어집니다. 사내 인프라 담당자에게 "제 노트북 MAC에 IP 예약 걸어주세요"라고 요청하는 편이, bat 파일 두 개를 관리하는 것보다 훨씬 빠릅니다. 요청할 때는 **유선·무선 MAC을 둘 다** 알려주세요 (`ipconfig /all`의 "물리적 주소").
</Alert>

## 자주 겪는 문제

| 증상 | 원인 | 해결 |
| :--- | :--- | :--- |
| SSID별로 설정했는데 집에서도 사무실 IP가 유지된다 | 어댑터 속성에 전역 고정 IP가 남아 있음 | 0단계 2)로 어댑터를 DHCP로 복귀 |
| 재부팅하면 설정이 원래대로 돌아간다 | TCP/IP 스택 손상, 서드파티 VPN·보안 프로그램 간섭 | `netsh winsock reset` + `netsh int ip reset` 후 재부팅 |
| [대체 구성] 탭이 안 보인다 | IPv4가 "다음 IP 주소 사용"(수동)으로 설정됨 | 일반 탭을 "자동으로 IP 주소 받기"로 변경 |
| 회사 Wi-Fi에서만 인증이 자꾸 풀린다 | 임의 하드웨어 주소(랜덤 MAC) 켜짐 | 해당 SSID 프로필에서 끄기 |
| 유선 연결이 1분쯤 걸린다 | 대체 구성의 DHCP 타임아웃 대기 | 정상 동작. 급하면 DHCP 예약으로 전환 |
| 도킹 스테이션을 바꾸니 스크립트가 실패한다 | 인터페이스 이름이 `이더넷 3` 등으로 바뀜 | 이름 하드코딩 방식(bat) 자체를 폐기 |
| IP는 맞는데 인터넷만 안 된다 | DNS가 사내 DNS로 고정된 채 남음 | DNS 서버 할당도 자동(DHCP)으로 |

## 유선 네트워크가 두 개 이상이라면

사무실 유선과 데이터센터 유선을 오가는 것처럼 **유선 네트워크가 여러 개**라면, 대체 구성 하나로는 부족합니다. 이때는 순서가 이렇습니다.

1. **1순위 — DHCP 예약.** 양쪽 네트워크 모두 예약을 걸면 PC는 무설정.
2. **2순위 — USB 유선 어댑터 분리 사용.** 어댑터가 다르면 IP 설정도 따로 저장됩니다.
3. **3순위 — 이벤트 트리거 자동화.** 작업 스케줄러에서 `Microsoft-Windows-NetworkProfile/Operational` 로그의 네트워크 연결 이벤트를 트리거로 PowerShell 스크립트를 실행하는 방식입니다. 결국 스크립트를 쓰긴 하지만, **사람이 실행을 기억할 필요가 없다**는 점에서 bat 수동 실행보다는 낫습니다.

3번은 관리 부담이 있으니, 가능하면 1번으로 밀어붙이는 편을 권합니다.

## 정리

- **Wi-Fi**는 알려진 네트워크 관리에서 SSID별로 IP를 저장하면 자동 전환됩니다. 이게 정석입니다.
- **유선**은 대체 구성으로 폴백을 걸 수 있지만, DHCP 서버가 없는 네트워크에만 통합니다.
- 무엇을 하든 **먼저 어댑터의 수동 설정을 비우세요.** 안 되는 사례의 대부분이 여기서 갈립니다.
- 애초에 고정 IP가 필요한 이유가 "서버가 내 IP를 알아야 해서"라면, **DHCP 예약**이 클라이언트 설정 전부를 없애줍니다.

바탕화면의 `office.bat`, `home.bat`은 이제 지워도 됩니다.
